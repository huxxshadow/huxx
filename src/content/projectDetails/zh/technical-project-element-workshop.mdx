## 我的职责

这是一个个人项目：一个模拟和渲染全部在 GPU 上运行的落沙沙盒。整个世界是 512 × 288 的元胞自动机，每一格都是一粒沙、一滴水、一缕烟或固体的一部分。

- **模拟**：元胞运动、44 种反应、热传导、带潜热的相变、流体与烟雾场、刚体，全部是 GPU compute pass，不使用 Godot 自带的物理。
- **渲染**：Radiance Cascades 2D 全局光照、被所穿过物质染色的光、次表面散射，以及用光影给平面世界带来纵深的 2.5D 视图。
- **优化**：通过大量优化，使每帧 GPU 耗时降到 3.5 ms，同时每一帧的输出逐字节不变。

## 光照

光照是基于 **Radiance Cascades** 的 2D 全局光照。每一格都可以发光（火、熔岩、灯、发光物质），每一格也都按 RGB 三通道消光，所以光穿过绿色的盐酸、蓝色的水或红色的玻璃会被染色，在墙上投出彩色的光。冰、晶体、果冻这类半透明材质会让光在内部散射（次表面散射），表面另有一层清漆负责锐利的高光。

在全局光照之外，还有独立的 pass 追踪穿过窗户的阳光、吊灯的光束和镜子反射的光束；最后经过泛光、自动曝光、AgX 色调映射和调色 LUT。

## 模拟

每个元胞把材质、温度、寿命和标志位存在一个 `rgba32ui` 像素里。运动使用 **Margolus 2 × 2 块**：网格被分成互不重叠的块，每个线程只重排自己块内的四格，没有写冲突；每个 tick 有 8 个子步，交替偏移块的位置。空气也是一种材质，所以粉末、液体、气体的沉浮都由同一个密度比较决定。

反应来自一张 256 × 256 的反应物对查找表，带概率和温度区间，在每个块内对相邻格成对求值。热量在格子之间扩散，相变会吸收或释放潜热。1/4 分辨率的流体求解提供热空气浮力和爆炸冲击，1/2 分辨率的介质场承载烟、蒸汽和火焰。

## 2.5D 视图

形体始终是二维的，纵深完全来自光影。最终画面由一个视图 shader 合成：每个像素的视线先穿过被当作几格厚的玩法层，再穿过由窗户、壁柱、岩壁组成的背景浮雕：

- **浮雕法线**：物体轮廓朝向或背离光源，边缘像浮雕一样受光。
- **界面**：视线在水、玻璃、冰的表面按折射率偏折；菲涅尔反射会再追踪回场景里。
- **背景**：浮雕按深度读取模糊的光照，带前景投影、水后的焦散和接触阴影。
- **空气感**：层间雾、空气透视、昼夜循环，镜头移动时有轻微视差。

## 性能

整帧预算是 16 ms（60 fps）。光照效果是一项一项加上去的，每加一项都会变慢，所以优化贯穿了整个开发过程，而不是最后一次性做完。下面按时间顺序记录每一步（RTX 5090，世界 512 × 288）。

### 第一步：先看清每一毫秒花在哪

先做了一个游戏内的性能面板（F3）：

- **分步耗时**：每个渲染步骤的 GPU 毫秒数，用条形图显示。
- **开销热力图**：2.5D 视图 shader 按像素统计背景、空气、前景三部分的采样次数，叠在画面上显示，再按物质换算成毫秒，能直接看出哪种物质最贵。
- **逐项测开销**：依次短暂关闭每个效果，用开 / 关的差值测出它实际占多少 GPU 时间。

### 第二步：逐像素的计算搬到世界分辨率

热力图显示最贵的是前景体积雾：它在最终画面的每个像素上做带抖动的步进。雾和光柱本身是平滑的，用不着这么高的分辨率，于是改为在 512 × 288 的世界分辨率上预计算一张雾贴图，画面合成时双线性采样。画面合成从约 1.0 ms 降到 0.13 ms，展厅整帧从 1.88 ms 降到 0.93 ms，抖动带来的噪点也一起消失了。

### 第三步：光束降到半分辨率

加入反射、折射光束之后，光束成了新的大头。光束沿路径把能量原子累加到缓冲里，原子写入的冲突是主要开销：

- 累加缓冲降到半分辨率；
- 每走两步沉积一次，不再双线性分摊到四个格子，原子写入约为原来的 1/8；
- 之后的模糊也在半分辨率上做 3 × 3。

光学台整帧 1.58 → 1.05 ms，展厅 1.29 → 0.94 ms，实验室 1.08 → 0.86 ms。灯光光束另外加了廉价预判：先沿直线探测 56 格，前方没有透明物或镜面就整条跳过；只有进入色散物质时才拆成多个波长，否则只追踪一条白光。

### 第四步：建立“画面不变”的回归测试

后来加入了阳光波前和 8 段光谱色散，白天场景涨到 5.5 – 7.9 ms，其中光束就占了 3.4 ms 以上。再往下优化要深入改 shader 的执行方式，必须保证不把画面改坏。

游戏在固定帧率下是确定性的（模拟的随机数以 tick 为种子），所以一个不改变结果的优化必须精确复现原来的画面。为此写了 `perf_check.py`：用固定时间步渲染 9 个场景（光照最重的地图、火焰场景和脚本演示）各 240 帧，取后半段的平均分段耗时，再把每张截图和优化前的参考图**逐字节**比较。只要有一个像素不同就报告最大误差；只有全部一致的改动才保留。

### 第五步：光束从串行改成并行

分段计时找出了两条串行链：

- **8 个波长依次计算**：一组光线里只要有一条碰到会色散的玻璃，整组都要把 8 个波长一个接一个追踪一遍。改为每个波长占一层工作组（`gl_WorkGroupID.z`），8 层同时运行。光束的沉积是整数原子加法，与执行顺序无关，所以结果逐位相同。
- **阳光探测是整帧最长的串行链**：640 条阳光射线，每条由一个线程从头走约 600 格，寻找第一个会改变光路的物质。新增 `sun_probe.comp`，把每条射线切成 32 步一段，每段一个线程并行探测；命中位置编码成 `0x7FFFFFFF − t`，用 `atomicMax` 保留最早的一次，答案与从头走完全一样。

| 场景 | 之前 | 之后 |
| --- | --- | --- |
| 彩窗大厅（封面） | 7.9 ms | 3.7 ms |
| 光学台 | 7.2 ms | 3.4 ms |
| 光影展厅 | 6.8 ms | 3.3 ms |
| 实验室 | 5.4 ms | 3.1 ms |

### 第六步：模拟搬进共享内存

- **液体横向扩散**：液体在一行里边扫描边移动，扫描必须串行。原来每个线程直接在全局图像上逐格读写；改为每 64 格的行段由一个工作组负责，64 个线程把这一段和它下方的支撑格并行载入共享内存，一个线程在共享内存里做同样的串行扫描，再由全组写回。0.18 – 0.25 ms → 0.05 ms。
- **压力求解**：流体压力用 Jacobi 迭代求解泊松方程，原来每次迭代一次 dispatch，共 20 次。128 × 72 的压力网格正好放得进一个工作组的共享内存，于是由一个 1024 线程的工作组在共享内存里跑完全部迭代，邻居掩码预先算好；求和顺序与原来一致，结果相同。0.18 ms → 0.09 ms。更大的网格仍走原来的路径。
- **空闲 pass**：没有玩家输入的 tick，命令 pass 只是把网格原样拷贝一遍，直接跳过。

模拟整体快了一倍，输出同样逐字节一致。

### 结果

在最重的场景、1536 × 864 分辨率下，每帧 GPU 耗时从 **7.9 ms 降到 3.5 ms**，9 个场景的画面与优化前逐字节一致。
