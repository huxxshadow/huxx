## 我的职责

这是一个七天的个人练习项目，从零在 Unreal Engine 5 里搭一套跑酷运动与镜头系统。除动画资产外，全部玩法系统、镜头逻辑与代码由我独立完成：

* **运动系统架构与实现**：把跑酷拆成翻越、贴墙跑与蹬墙跳、跳跃与落地、滑铲、冲刺、空中控制、转身混合等模块，各自实现为可拆卸的积木式角色组件。
* **3C 手感调校**：围绕"速度感"而不是"真实感"定基调，设计速度档位、进出状态的条件与冷却、动画与代码之间的分工边界，并为每个可感知的量都留出可调参数。
* **镜头系统与镜头叙事**：实现一套由速度、状态与事件驱动的相机动态系统，覆盖迟滞、视野、臂长、滑动变焦、转向构图、畸变、抖动、腾空构图与视角窗口，并对外暴露一组可供过场与剧情复用的镜头通道。
* **调试与验证工具**：写了一套主/从双角色的对比演示装置，开演时自动比对两边所有自定义组件的参数差异并列在屏幕上，用来验证一次调参到底改了什么。

## 项目细节

《跑酷运动系统》是我用七天时间完成的一个 Unreal Engine 5 练习项目，目标是把跑酷类游戏的运动系统与 3C 设计从头走一遍。参考对象是我很喜欢的《Ghostrunner》与《Mirror's Edge》——它们的共同点是，**动作看上去合不合物理并不重要，重要的是速度是否连续、镜头是否让人相信自己在飞**。

### 设计前提：为速度感牺牲真实性

整个项目最先定下的一条原则是：**当手感与物理真实冲突时，无条件让位给手感。** 比如：

* **贴墙跑不切移动模式**：角色全程留在 `MOVE_Falling`，只把 `GravityScale` 清零，然后由组件每帧完整覆写速度。这意味着贴墙期间的"先平后沉"是一条我自己写的可调曲线，而不是引擎重力积分出来的结果——曲线想怎么弯就怎么弯，代价是绕开了 CharacterMovement 的网络预测，这套系统因此是单机专用的。
* **滑铲由速度驱动，不由 root motion 驱动**：滑铲动画的循环段是恒定速度的，而滑铲这个动作的意义恰恰在于速度在衰减。所以动画只负责表现，速度曲线由代码算——动画服从手感，而不是手感服从动画。
* **翻越故意不做攀爬**：翻越被分成跨栏、撑越、上台三类，每一类都是"一个蒙太奇打完收工"的结构。攀爬需要引入"挂在墙上"这个持续状态和一整套悬挂移动，会把节奏拖慢，与这套系统追求的连续性相冲突，因此被排除在外。

### 运动系统：组件化的模块拆分

运动能力被拆成一组挂在角色上的独立组件，各自负责一件事：

* **翻越**：向前检测障碍并分类（薄且矮 → 跨栏，薄但背面没地 → 撑越，厚 → 上台），再按起手速度选择站立 / 行走 / 奔跑三档蒙太奇。这一块反过来交给 root motion 与 Motion Warping。

* **跳跃与落地**：起跳瞬间锁存水平速度，供动画按站立 / 走 / 跑 / 冲刺四档混合；同时跟踪腾空最高点算出坠落高度，触地时据此决定是普通落地还是翻滚。所有混合权重都用锁存值，整个空中阶段保持稳定，不会因为空中微调而抖动。
* **滑铲**：入场条件、速度衰减与退出方式（站起、保持蹲伏、蹲走、起身走、起身跑）分开配置。
* **冲刺与空中控制**：冲刺负责速度档位切换并把强度推给镜头畸变；空中控制单独管理腾空时的转向能力，让空中修正既不失控也不僵硬。
* **转身混合**：处理原地转向与移动中的朝向插值，配合八向移动的混合空间。

角色本身则由一棵状态树（State Tree）统筹，配合 GASP 的八向移动与倾斜混合空间驱动动画层。整套自定义代码约 12,700 行 C++，分布在九个组件与一个演示装置里。

### 镜头叙事：把镜头变成可编排的语言

这个项目真正想探索的部分，是**镜头能不能主动叙事，而不只是被动跟随**。为此镜头系统对外暴露了几组可以被玩法、过场或剧情脚本调用的能力：

* **滑动变焦（dolly zoom）**：起步时相机推近、FOV 张开，背景向后拉伸退开，做出推背感。补偿强度可调——拉满时主角大小被严格锁死，变焦感最纯粹，但也最容易晕；调到 0.6~0.8 是"有点那意思但别太晕"。参数取负号则反过来：背景被压扁怼上来，那是"愣住 / 意识到什么"的镜头。它既能由起步条件自动触发（带站定时长与冷却，避免走走停停时镜头不停变焦），也能被显式调用一次，给过场或拾取关键道具复用。
* **外部镜头通道**：roll、臂长、FOV、构图偏移四条通道可以被外部整体接管，**每条通道各有自己的淡入淡出时长**。这是我认为最接近"镜头语言"的一处设计——四项同时到位会显得机械，而 roll 立刻跟上、构图偏移慢慢滑过去的那种错落感，才像是一次有意识的运镜。贴墙跑就是这套通道的第一个使用者：贴墙时给出 -20° roll、臂长收近、FOV 张开与横向构图偏移。
* **视角窗口**：可以限定玩家在某段时间内能看的方向范围。窗口在开启瞬间先"包住"当前视角、再收拢到配置值，避免硬夹产生的跳变；软边界之外会被持续往回带，硬边界则完全推不动。贴墙跑期间用它把视角约束在墙面朝向附近——这本质上是**用镜头限制来引导注意力**，是叙事手段而不是操作限制。
* **时间缩放**：跳跃到达最高点时压低全局时间倍率再滑回来，做出一个顿挫。它配了普通与夸张两套参数：高空那一下需要更长的滞空感，普通小跳只要一个短促的顿挫。更关键的是可以单独给玩家角色补偿时间倍率——世界慢下来而玩家保持原速，就是子弹时间；两者一起慢，就是纯粹的节奏停顿。减速触发前还会向下做一次预测性检测，避免在马上要落地的地方给出一个没有意义的慢镜头。

### 验证工具：让调参可被看见

手感调参最难的地方是说不清"这次改了什么"。所以我额外写了一个演示装置：场景里放主 / 从两个角色，从属角色按指定改写运行不同参数，开演时自动把两边所有自定义组件的可编辑属性逐一导出比对，**把差异直接列在屏幕上**。

这样录出来的对比视频不需要旁白解释，画面本身就写着"这条录像在演什么"——同一段路线，左边和右边差的就是屏幕上列出的那几个参数。
