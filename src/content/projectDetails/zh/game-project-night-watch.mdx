## 我的职责

《守夜人》是我在网易推进的一个实验性课题，探索的是 **AI 原生游戏**与 **AI 游戏开发工作流**：当内容生产可以交给模型时，玩法本身该长成什么样，开发流程又该如何组织。我在其中主要负责：

* **AI 原生玩法的研究与设计**：以「内容可以由模型在运行时生成」为前提反推玩法结构——把角色、装备、材料、地点、事件、状态统一成卡牌，让新增内容不需要新增界面；把随机遭遇设计成只渲染氛围、不明说结果的赌注，使模型最擅长的文本变体直接成为可玩的变量。
* **游戏底层框架的设计**：设计卡牌数据模型与「拖入使用槽 → 合成 / 穿戴 / 进入 / 使用」的单一操作路径，并划分战斗、装备槽位、伤害类型与抗性、副本推进、元成长等系统的层次与边界，让内容持续扩张时不必改动核心逻辑。
* **LLM 运行时内容管线设计**：设计事件卡与敌人卡的生成协议——JSON-only 输出、kind 与结算结果的一致性校验、白名单与 tier 区间、数值由代码 roll、文风与防剧透约束、二次校对 pass、缓存池与超时降级，把文本创意交给模型、把规则与数值留在代码里。
* **AI 协作产线与集成**：制定文风基调与美术规格，串起程序、美术、音乐、剧本各环节的 AI 生成与人工审校流程，统一 80 张卡面素材的三档尺寸，并把整套内容集成进 React + Zustand + Three.js 的前端。

## 项目细节

《守夜人》是一款维多利亚哥特题材的 AI 原生卡牌 Roguelike。游戏的核心理念，是在一套玩法直观但具有足够系统深度的卡牌框架之上，通过定义严格的内容、数值与规则约束，让 AI 内容能够稳定地参与局内随机拓展，从而使游戏具备大量局外成长与局内构筑变化，并进一步实现传统 Roguelike 难以达到的、真正意义上的近乎无限的构筑可能。

游戏基于 Web 端开发，玩家将扮演一名提灯的守夜人，登上一列危险的列车，在湿冷走廊、头等舱包厢、餐车、锅炉房与被雾吞没的车厢之间不断前进，通过收集材料、合成装备、调整构筑与应对遭遇，在一次次战斗中寻找存活下来的可能。

在玩法框架上，《守夜人》参考了《堆叠大陆》和《密教模拟器》的卡牌交互设计，将角色、装备、材料、地点、事件、状态等内容统一抽象为可拖拽的卡牌对象。玩家通过“将卡牌拖入使用槽”这一单一操作，完成合成、穿戴、进入地点、使用道具等核心行为。这样的设计降低了操作理解成本，同时为后续内容扩展提供了高度统一的接口：新增内容不需要新增复杂界面，只需要作为新的卡牌类型或卡牌数据接入系统。

需要说明的是，本页顶部 **Play** 链接提供的 Web 体验版本目前没有部署 AI 后端服务，因此局内的事件卡与敌人卡不会实时生成，而是走预置的静态卡池。系统、流程与数值完整可玩，只是随机内容的变化范围被固定在静态池之内。

### 卡即一切：一条动词、六类卡牌

游戏里没有独立的背包界面、锻造界面或地图界面，卡牌被拖进使用槽时解锁哪一个动作，只取决于它自身的类型：

* 材料 → **合成**（凑齐配方就能打造装备）；
* 装备 → **穿戴**（进入主手、副手、头部、身体、手部与两个饰品槽）；
* 地点 → **进入**（把这张车厢卡当作一次副本推进）；
* 消耗品 → **使用**（急救包一类的即时回复）。

教程也因此可以极短——两步：把两个齿轮拼成齿轮短棍，把齿轮短棍装到主手，玩家就学完了全部操作。

### 战斗：把决策提前到备战阶段

战斗本身是自动进行的回合制——装备自动生效，玩家在战斗中不需要（也无法）操作，只能长按加速。这不是为了偷懒，而是一个明确的设计取舍：**把所有决策提前到你推开车厢门之前。**

真正的博弈发生在伤害类型与抗性的匹配上。游戏里有四种伤害：钝击、利器、火器，以及对非人克制的光属性。而敌人被分成两类立场：

* **人类一侧**（湿透的男人、潜伏的杀手、挑枪杀手、被卷机械师）——多数吃利器与火器，湿的东西怕火，机械化的东西怕燎；
* **非人一侧**（低语者、雾中怨灵、非人之物、雾之主宰）——物理与雾伤几乎不动分毫，唯有光、银与火才能让它散一散。

于是每张地点卡都变成一道配装题：进「灵异低语」的车厢前，你会想带上银十字与气死风灯；进「机械间」，齿轮短棍与管钳更趁手。带错装备的代价不是操作失误，而是整场战斗从第一回合就注定了。

### 合成、词条与拆解：让每一次失败都留下东西

材料是这个循环的血液。齿轮、生锈铁片、皮革、火药、煤气、血晶、银、布料、玻璃、铁锭、灯油、雾骨灰、雾之精粹——十三种材料对应不同的车厢特质，湿冷区给你皮革与铁片，机械间给你齿轮，神龛给你银，浓雾深处才凝得出雾之精粹。

合成产出的装备会**按稀有度随机附带命名前缀词条**：锋利的、坚固的、精铸的、银镶的、雾蚀的、血浸的……同一张配方因此不会产出两件完全相同的装备，也让「再打一把」始终有理由。而拆解系统提供了反向通路：不合用的装备可以拆回材料，重新投入下一次合成。

这套设计的目的是让**失败具有沉淀**。一局倒在餐车里，玩家带不走等级，但带走了对配方、抗性与车厢特质的理解，以及下一局开局时更聪明的第一手。

### 副本结构：二选一的推进与被隐藏的结果

进入一张地点卡后，推进方式是**每一步在两处遭遇之间择一面对**。遭遇分为战斗与非战斗两类：搜刮、陷阱、神龛献祭、低语的诱惑、暂歇的角落……而卡面上写的只是氛围。

这是我在事件设计上定下的硬规则：**描述只渲染征兆、气味与声响，绝不明说会给什么、扣多少血、是否开战。** 「墙角的阴影里搁着一只蒙了灰的木箱，铜搭扣锈成了绿色」——它可能是急救包，也可能是伏击。玩家必须凭直觉与对车厢特质的理解下注，而不是读一遍收益再点确定。

部分车厢还会岔出支线：机械间从头等舱岔出，货运车厢从连接处岔出，小礼拜堂与雾厢从锅炉房岔出。支线通常特质更极端、掉落更专一，是玩家为下一次配装主动绕的路。

### Roguelike 元成长：把上一局的经验做成开局卡

每一局结束——无论通关还是倒在半路——都会结算经验，推动「守夜人等级」。升级解锁的不是数值加成，而是**一张会出现在下一局开局的卡**：强韧体魄提高生命上限，搏杀本能提高攻击，守夜警觉让你开局就戴着防毒面具，行囊与备粮多给几份材料，雾中拾遗直接塞给你一枚血晶。

把元成长表达为卡牌而不是数字，是为了保持世界观与界面的一致：玩家在结算页看到的是「新解锁的初始加成卡」，下一局开局时它就真的躺在你的牌桌上。

### LLM 运行时内容生成：把创意交给模型，把规则留在代码里

这个项目在技术上最核心的部分，是事件卡与敌人卡的**运行时 LLM 生成管线**。玩家每次进入一节车厢，事件与敌人可以不来自静态卡池，而是由模型即时写出来——但整条管线是被严格约束的：

* **结构约束**：只输出 JSON，禁止任何解释；每张事件必须声明 `kind`（战斗 / 普通），且 `kind` 必须与描述和结算结果一致——写成战斗就必须真触发战斗；批次里约一半战斗、一半普通。
* **内容白名单**：图标、可给出的物品、敌人定义 ID、行为 ID 全部来自白名单，并附带兼容表；掉落表由代码指定，模型不可自选。
* **数值主权在代码**：模型填写的 HP / 攻击只需落在给定 tier 区间内，实际数值以代码 roll 为准——**模型只负责文本质量**。
* **文风约束**：华丽、压抑、神秘、轻微克苏鲁；复古蒸汽朋克用词（铜锈、漆木、煤气灯、蒸汽、湿气、低语），禁现代词汇与出戏比喻；第二人称叙述；「异常被看见，但不被解释」。
* **防剧透模糊化**：标题与描述只写氛围与征兆，不得明说奖励、伤害或是否开战；战斗事件要贴合本副本敌人的形象，但不得直呼敌人全名、不得剧透结果。
* **二次校对 pass**：第一轮生成后再跑一遍「校对员」提示词，检查文风、模糊度、与敌人氛围的贴合度，并把与本局已给过的装备重复的掉落换成没给过的一件。
* **上下文感知**：生成时会带上玩家的 Build 倾向（火器路线、堆光克非人、近战利钝、裸拳流）、当前压力（长期低血）、近期选择与近期敌人，让文本贴着这一局的实际处境走。
* **降级与缓存**：生成结果进入缓存池，可「换血」刷新；请求超时或失败时静默降级回静态卡池，玩家不会看到报错，只会看到一张写得规矩些的卡。

这条管线体现的其实是一个设计立场：**LLM 适合做氛围与文本的无限变体，不适合做游戏的规则裁判。** 所以我把它放在最外层——它可以写出无数种「墙角有个箱子」，但箱子里有什么、你会掉多少血、这一战怎么打，始终由代码说了算。

### 表现层与性能档位

前端使用 React + Zustand + Immer 管理状态，Three.js 负责 3D 卡牌的翻转、发牌与战斗运镜。考虑到网页端设备差异极大，我把渲染拆成四档画质：**纯 2D 牌桌**（关闭 3D，低端机最流畅）、**3D 卡牌但无战斗运镜**、**超采样 + 半量粒子**，以及**完整 3D + 战斗运镜 + 超采样 + 满粒子**。存档、音量与画质写入 localStorage，并配有错误边界——界面崩溃时提供「重置存档并刷新」，而不是让玩家卡死在白屏上。

音频方面，游戏包含一首雾夜基调的 BGM、一组卡牌与战斗音效，以及三段用于开场引文的旁白语音。

### AI 协作产线：哪些内容是批量生成的

游戏里的绝大部分内容，是在搭好 AI 工作流之后批量生成的：

* **卡面美术**：80 张卡牌插画（12 张角色、24 件装备、13 种材料、15 个地点、10 类事件、5 张元成长卡与 1 张道具），统一风格后按三档尺寸导出，共 240 个素材文件。
* **卡牌文案**：27 张静态事件卡，40 个敌人预设变体（8 种地点特质 × 5 个）的名称与登场旁白，24 件装备与 13 种材料的描述，12 种前缀词条，以及每个地点的场景描写与胜负结算文本。
* **本地化**：中英两套完整文本，约 340 条界面词条加上全部卡面文案。
* **音频**：1 首雾夜基调 BGM、8 个卡牌与战斗音效、3 段开场引文旁白。
* **程序**：React + Zustand + Immer + Three.js 的前端实现，包括卡牌交互、战斗结算、合成与拆解、存档与画质档位。

我做的是先搭出规则、数值与结构的骨架——卡牌类型、伤害与抗性、掉落表、地点特质、生成协议与文风约束——再让 AI 在骨架允许的形状里批量产出内容，最后逐张审校、替换与回收。
