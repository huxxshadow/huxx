## 我的职责

在这个为期三个月的独立游戏开发项目中，我独自完成了从玩法设计、程序开发到测试迭代的完整开发流程，主要职责包括：

* **核心玩法设计与原型搭建**：围绕“速度即力量”这一核心概念，设计了角色移动、速度成长、攻击反馈与生存压力之间的循环关系，并将其实现为可持续推进的跑酷战斗玩法。
* **游戏系统架构与功能开发**：基于 Unity 与 C# 搭建整体项目架构，完成了角色控制、战斗系统、程序化地图生成、技能成长、UI 管理、音效控制与视觉反馈等核心模块的设计与实现。
* **程序化关卡与数值节奏设计**：设计并实现了基于区块拼接与噪声算法的地图生成系统，使关卡在保持可玩性的同时具备一定随机性与重复游玩的新鲜感；同时负责敌人密度、障碍频率、速度阈值与成长曲线的数值调优。
* **Roguelite 成长机制设计**：实现了局内随机强化与局外永久成长相结合的双层成长结构，使每次游玩既有即时构筑变化，也有长期解锁目标，从而增强游戏的重复可玩性。
* **测试迭代与体验优化**：组织并参与课堂试玩测试，根据玩家反馈持续调整新手引导、速度条可读性、敌人刷出节奏和操作手感，对整体难度曲线与用户体验进行了多轮优化。

## 项目细节

《Speed Pixel》是我在 **GAME3005: 2D Platform Programming** 课程中独立完成的期末项目，也是一次较为完整的 2D 平台动作 Roguelite 游戏 Demo 实践。项目以极简像素风格为视觉基础，结合高速移动、弹幕战斗与局内外成长机制，尝试构建一个强调“节奏感、速度感与构筑感”的动作游戏体验。玩家将控制一个像素方块角色，在不断向前推进的世界中穿越障碍、维持高速、击败敌人，并在一次次失败与重开中逐步解锁新的能力与玩法路线。

整个项目的设计核心围绕一句非常明确的机制理念展开：**速度即力量**。在本作中，速度并不仅仅是移动能力，而是直接与玩家的攻击强度、生存状态和战斗效率绑定的核心资源。玩家必须通过奔跑、跳跃、冲刺、贴墙滑行、抓钩摆荡等动作持续维持动能；一旦速度下降，攻击效果会显著减弱，甚至会进入危险状态。如果速度长时间归零，角色将直接死亡。这种设计使移动系统不再只是穿越地形的手段，而是与战斗、资源管理和生存决策深度融合，构成了整个游戏体验的基础张力。

### 核心玩法设计：速度驱动的战斗循环

与传统平台动作游戏不同，《Speed Pixel》强调玩家必须在高速状态下完成战斗与穿越操作。游戏中的速度条不仅是一个显示组件，更是引导玩家行为的重要反馈系统。随着速度上升，玩家会进入不同的速度阶段，并获得更强的伤害输出、额外攻击效果或更高效的清怪能力；当速度跌破关键阈值时，角色输出能力会明显下降，战斗与生存压力迅速提升。这样的设计让玩家始终处于“继续加速”与“避免失速”的双重驱动之中。

为了支撑这一核心循环，我设计了多种与速度联动的移动机制。基础层面包括奔跑与跳跃；进阶层面则加入了能量球冲刺、贴墙滑行以及抓钩摆荡等高机动动作。其中，能量球冲刺参考了《Ori and the Blind Forest》中方向冲刺的设计思路，允许玩家在接触特定交互点后朝指定方向迅速位移，从而跨越高风险区域或维持连贯节奏。抓钩机制则进一步提升了地图 traversal 的表现力，使玩家能够在复杂地形中完成高速摆荡与位移衔接。这些机制共同构成了一个高度依赖节奏与路线判断的移动系统。

### 战斗系统：高速压制与弹幕输出的结合

在战斗设计上，我没有采用传统的近战连招系统，而是将“高速移动”与“自动或半自动火力输出”进行结合，使玩家在持续前进的同时完成清怪与压制。玩家可以通过速度直接造成撞击伤害，也能在达到一定速度阶段后释放能量波，同时还可以装备不同类型的炮塔或武器模块，发射具有差异化效果的子弹。

我设计了多种武器表现形式，包括单发高伤、双发平衡、三连低伤高频，以及具有范围爆炸能力的火箭类攻击。这些武器不仅在数值上存在差异，也会影响玩家在战斗中的节奏与构筑方向。例如，高爆发武器更适合处理精英敌人与关键威胁目标，而高频弹幕武器更适合在高速推进中快速清理密集敌群。通过这种设计，战斗系统与 Roguelite 构筑系统形成了较强的联动关系，让玩家在每局中都能根据强化选择形成不同打法。

在子弹系统实现上，我构建了支持直线、追踪、穿透和爆炸等多种行为模式的统一逻辑结构，并结合对象池减少高频生成销毁带来的性能开销。特别是在敌人密度较高、屏幕投射物数量较多的情况下，这种结构能保证战斗画面仍保持稳定和清晰。

### Roguelite 成长结构：局内构筑与局外成长并存

为了提升重复游玩的价值，我在项目中加入了较完整的 Roguelite 成长框架。玩家在每次失败后会返回起点，但可以保留游戏中获得的资源，用于解锁永久升级、能力分支和新装备；而在单次流程中，玩家又能通过随机强化选项获得临时增益，从而形成具有变数的局内构筑体验。

这种“双层成长”机制能够同时满足短期反馈与长期目标：一方面，玩家每次开局都可以尝试新的强化组合，获得不同的战斗风格；另一方面，即使失败，也能通过累积资源感受到持续成长，降低重复挑战的挫败感。在实现上，我为技能树系统设计了基于唯一 ID、解锁依赖与花费条件的管理逻辑，通过数据驱动方式管理技能与能力项，使后续扩展新升级内容更加方便。

### 程序化地图生成：兼顾随机性与可玩性

地图生成系统是这个项目中我投入较多精力的模块之一。考虑到游戏需要不断向前推进、强调重复游玩和路线变化，我采用了基于模块化区块拼接的程序化生成方式。整体场景由一系列具有不同功能和地形特征的小型预制块组成，再通过主路径算法和分支生成逻辑拼接成完整关卡流程。

主路径主要使用噪声函数来生成自然的高低起伏，确保整体地形变化具有一定节奏感；分支路径则根据参数控制生成频率、距离和难度，避免地图在随机化之后变得不可通过或缺乏趣味。系统同时加入了碰撞检测、路径连续性检查与局部密度控制，以减少区块重叠、跳跃断层和无效空间问题。通过这种方法，地图既能保持较强的重玩差异，又不会破坏平台动作游戏对“可读性”和“可预判性”的基本要求。

### 视觉风格与界面设计

在视觉层面，《Speed Pixel》采用了极简像素美术风格，强调高对比度、强识别性与高速运动下的可读性。由于游戏节奏较快，我在设计视觉反馈时优先考虑信息传达效率，而不是复杂装饰。角色、敌人、陷阱与可交互元素都尽可能使用清晰的几何轮廓与明确的颜色区分，让玩家可以在高速移动中快速识别危险和路径机会。

UI 设计则遵循“极简但高辨识度”的原则。速度条是整个界面最关键的信息组件，因此我在位置、色彩变化和阶段反馈上做了重点设计，使玩家能够在不分散过多注意力的前提下掌握当前状态。除此之外，我还设计了升级选择界面、局外商店界面以及结算界面，用于承载 Roguelite 玩法中的成长与反馈环节。为了增强速度感与打击感，项目中还加入了粒子特效、受击形变、状态变化颜色反馈以及高速状态下的运动视觉强化效果。

### 技术实现与工程组织

项目使用 **Unity 6000+ LTS** 与 **C#** 开发，并结合 **URP** 实现像素风格下的后处理视觉表现。在架构方面，我将系统拆分为多个独立模块，包括游戏流程管理、玩家控制、武器与子弹系统、地图生成、技能树、UI 管理、音频控制和特效控制等，并通过事件机制减少模块之间的直接耦合。核心管理器采用统一的单例基类管理生命周期，运行时数据则结合配置与状态数据进行组织，以便后续迭代和功能扩展。

为了提升开发效率和可维护性，我还使用了 **DOTween** 处理 UI 与角色反馈动画，借助 **Odin Inspector** 提升编辑器配置效率，并通过统一的输入控制和时间控制逻辑来管理暂停、结算与非战斗状态下的交互行为。在性能优化方面，重点处理了地图区块加载卸载、子弹与特效对象池管理，以及后处理效果与音频播放的资源消耗问题，以保证项目在开发阶段具备较稳定的运行表现。

### 测试与迭代：从课堂试玩中优化体验

在项目完成阶段，我参加了课程组织的课堂试玩展示，并邀请其他同学体验游戏。这是我第一次将自己的作品交给较多玩家直接上手测试，也因此获得了非常真实和有价值的反馈。测试中比较集中的问题包括：教程文本信息过多，影响了前期体验节奏；速度条的可读性还可以继续提升；后期敌人压力不足，导致游戏紧张感下降；部分操作虽然设计上有深度，但首次体验时引导不够直观。

针对这些问题，我后续对项目进行了多项调整。例如，在新手教学中减少了大量文字说明，改为更直观的视觉提示与渐进式引导；在难度设计上提高了后期敌人出现频率，并加入更具有速度压制能力的敌人与障碍；同时对界面信息层级和控制反馈进行了优化，让玩家更容易理解“维持速度”的核心目标。这次测试经历不仅帮助我发现了设计盲区，也让我更深刻地理解了可玩性验证和用户反馈在游戏开发中的重要性。
