## 担当業務

Global Game Jam 2026 香港向けに48時間で開発されたこのチームプロジェクトにおいて、チームリーダー・メインプログラマー・ゲームデザイナーを担当しました。全体的な開発フローの組織・コアメカニクスの実装・ビジュアルの統一が主な責務でした。具体的な業務内容は以下のとおりです。

* **チームコラボレーションとパイプラインの構築**：チームリーダーとして9人チームを率いてプロジェクトの立ち上げ・タスク分解・バージョン統合・迅速な反復を完成させ、Game Jam の高プレッシャーなペースに適した協力ワークフローを確立して、ゲームプレイ・アート・プログラム・オーディオが並行して進められるようにしました。
* **コアゲームプレイとレベルロジックの設計**：「Clipping Mask」というコアコンセプトを中心にゲームメカニクスを設計し、プレイヤーがステッカーのマテリアルを変えることでシーンのルール・移動方法・パズルロジックに影響を与えられるようにして、プラットフォームと謎解きを組み合わせたレベル体験を構築しました。
* **カスタムグリッドと TileMap システムの開発**：カスタム物理ルールをサポートするグリッドシステムを構築し、設定可能なルールの TileMap ソリューションを拡張して、異なるマテリアルゾーン・トラップタイル・特殊インタラクションを統一されたシステムで駆動して素早く反復できるようにしました。
* **シェーダーとビジュアルの磨き上げ**：Unity 2D シェーダーに基づくアウトラインステッカーエフェクトと CRT ポストプロセッシングを実装し、プロジェクト全体のアートスタイルを統一・強化して、限られた開発時間内でゲームの識別性と画面の完成度を向上させました。

## プロジェクト詳細

*Eel On Mask（鳗！）*は、**Global Game Jam 2026 Hong Kong** 向けに **48時間**で開発された2D パズルプラットフォームゲームです。プレイヤーは主人公 Eel となって神秘的な **「Clipping Mask」** 能力を使ってステッカーのマテリアルを変え、異なる世界を旅して謎を解き、物語の背後にある真実に少しずつ迫っていきます。プロジェクトはその後整理・補完されて Steam に正式リリースされ、無料インディーゲームとして公開されています。

### チーム組織と48時間の迅速な開発

本プロジェクトは Game Jam で誕生したため開発時間が極めて限られており、チームの協力効率そのものがプロジェクトを成功させられるかどうかの鍵でした。チームリーダーとして、プロジェクト開始時点で素早くコアクリエイティブ方向を確定し、「短時間で完成でき、かつ識別性がある」という目標を中心にチームのゲームプレイ確定・タスク分解・優先順位付けを組織しました。

推進過程では、短期間開発に適した協力パイプラインを確立しました。まずゲームプレイプロトタイプを検証し、徐々にレベル・アート表現・演出コンテンツを追加していきます。高頻度の同期・タイムリーな連携・素早いバージョンマージにより、チームはわずか2日間で一貫した開発リズムを維持し続けることができ、複数人が並行開発する際によくあるリソースの不整合やシステムコンフリクトの問題を回避しました。この経験は、高プレッシャーな状況下でクロスファンクショナルな小チームの協力を推進するスキルをさらに積み上げる機会となりました。

### Clipping Mask：グラフィックのコンセプトをゲームメカニクスへ

本プロジェクトの最もコアなデザインは、画像編集ソフトウェアの **Clipping Mask** コンセプトを操作可能で理解しやすいゲームルールへと転換させることでした。プレイヤーに「プラットフォーム + 謎解き」の組み合わせだけでなく、オブジェクトのマテリアル自体を変えることで世界の動き方に影響を与える楽しさを体験してほしいと考えました。

デザイン上、これはシーンの要素がもはや静的な背景や普通の障害物ではなく、「ルール属性」を持つ変化可能なオブジェクトであることを意味します。プレイヤーはメカニクスを通じて特定のステッカーオブジェクトのマテリアルを変えることで、その衝突属性・サポート能力・環境フィードバックに影響を与え、新たなルート開拓・障害突破・空間と論理関係に基づいて設計された謎の解決ができます。このデザインにより「マテリアルの変化」は単なる視覚効果ではなく、レベルの進行に直接参加するものとなっています。

メカニクスの伝達を十分に明確にするために、レベルデザインにおいて段階的な導入アプローチを採用しました。まず単一のルールを理解させてから、異なるオブジェクト・異なるマテリアル・空間レイアウト間の組み合わせ関係を徐々に重ねていきます。これにより入門ハードルが高くなりすぎないようにしながら、限られたフロー内でもゲームが一定の戦略性と探索感を持てるようにしました。

### カスタムグリッドシステムとルール駆動 TileMap

この「ルール可変」なゲームプレイをサポートするために、**カスタム物理ロジックを持つグリッドシステム**を実装し、その上に特殊ルール拡張をサポートする **TileMap システム**を構築しました。静的なコライダーだけに依存する従来のアプローチと比べ、同じエリアが異なる状態で異なるインタラクション動作を示す必要がある本プロジェクトには、この方式がより適しています。

レベルエリアを統一されたグリッドデータ構造に抽象化することで、異なるマテリアル状態での通行可能性・衝突ロジック・トラップの応答をより効率的に処理できます。コードレベルでは特殊なケースごとにハードコーディングするのではなく、ルール設定によって異なるタイルの動作を駆動します。このデザインは一方でシステムの拡張性を向上させ、もう一方でレベル構築効率を大幅に高め、Game Jam 環境での高頻度な試行錯誤と迅速な反復に特に適しています。

実際の結果として、このシステムは非常に短い時間で安定したロジックを持つシーンインタラクションの完成を助け、後からより多くのマテリアルエフェクトや特殊なレベルメカニクスを追加するための余地も残しました。

### シェーダーでステッカー世界のビジュアル言語を統一する

ビジュアル表現の面では、プロジェクト全体のスタイルの統一を重点的に担当しました。Game Jam チームは開発期間が短くアセットの出所や制作方法が多様なため、統一処理をしないと最終的な画面がスタイルの断絶を起こしやすくなります。そのため **Unity 2D シェーダー**でコアビジュアル要素を再処理し、プロジェクトの「ステッカーの世界」という設定により適したものにしました。

まず**アウトラインステッカーシェーダー**です。このエフェクトはゲームオブジェクトのエッジ感と階層感を強化し、プレイヤーがビジュアル的にインタラクト可能なオブジェクトと環境背景をより区別しやすくするとともに、「ステッカーが切り取られ・重ねられ・置き換えられる」というテーマ感をさらに強化します。次に **CRT ポストプロセッシングエフェクト**を加えました。微妙なスキャンライン・色のズレ・スクリーンの質感を通じて、作品全体に統一された視聴覚的雰囲気を加えています。このエフェクトは識別性を向上させるだけでなく、限られた時間で完成したアートアセットがより自然に一体的なまとまりとして融合するのを助けました。

### Game Jam プロトタイプから正式リリースへ

*Eel On Mask* は短期間のイベントでのプロトタイプ展示にとどまらず、ジャム後にさらに整理・修正して Steam リリースへと進みました。Game Jam から生まれたインディーゲームとして、強烈なコアコンセプトを保ちながら後続の磨き上げを通じて完成度と遊び応えを徐々に補完しました。

このプロセスで学んだことは、Game Jam プロジェクトの価値は「短時間でゲームを作り終える」だけにあるのではなく、コアメカニクスが成立するかどうかを検証し、チームがそのメカニクスを中心に効率的に協力できるかどうかを確認することにもあるということです。*Eel On Mask* が最終的に48時間のプロトタイプからプレイヤーへ正式に公開できる作品へと成長できたことは、そのコアデザインが十分な拡張性と表現力を持っていることも示しています。
