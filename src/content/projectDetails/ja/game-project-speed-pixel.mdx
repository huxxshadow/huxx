## 担当業務

この3ヶ月間の独立ゲーム開発プロジェクトにおいて、ゲームプレイデザイン・プログラム開発・テストと反復まで完全な開発フローを独力で完成させました。主な業務内容は以下のとおりです。

* **コアゲームプレイのデザインとプロトタイプ構築**：「スピードは力」というコアコンセプトを中心に、キャラクターの移動・スピード成長・攻撃フィードバック・サバイバル圧力の循環関係を設計し、継続的に前進するパルクール戦闘ゲームプレイとして実装しました。
* **ゲームシステムアーキテクチャと機能開発**：Unity と C# でプロジェクト全体のアーキテクチャを構築し、キャラクターコントロール・戦闘システム・プロシージャルマップ生成・スキル成長・UI 管理・オーディオ制御・ビジュアルフィードバックなどのコアモジュールの設計と実装を完成させました。
* **プロシージャルレベルと数値ペースのデザイン**：チャンクアセンブリとノイズアルゴリズムに基づくマップ生成システムを設計・実装し、遊び応えを維持しながら一定のランダム性と再プレイのフレッシュさを持つレベルにしました。またエネミー密度・障害物の頻度・スピード閾値・成長カーブの数値チューニングも担当しました。
* **ローグライト成長メカニクスの設計**：ランダムなインラン強化と永続的なメタ成長を組み合わせた二層成長構造を実装し、毎回のプレイに即座のビルドの変化と長期的なアンロック目標を持たせることで再プレイ性を高めました。
* **テスト・反復と体験の最適化**：クラス内プレイテストを組織・参加し、プレイヤーのフィードバックに基づいてチュートリアル・スピードバーの可読性・エネミーのスポーンペース・操作感を継続的に調整して、全体的な難易度カーブとユーザー体験の複数回の最適化を行いました。

## プロジェクト詳細

*Speed Pixel* は、**GAME3005: 2D Platform Programming** の授業で独立して完成させた期末プロジェクトであり、比較的完全な2Dプラットフォームアクション ローグライトゲームのデモです。極めてシンプルなピクセルアートスタイルをビジュアル基盤として、高速移動・弾幕戦闘・ランとメタの成長メカニクスを組み合わせ、「リズム感・スピード感・ビルド感」を強調したアクションゲーム体験の構築を試みています。プレイヤーはピクセルのブロックキャラクターを操作して常に前進する世界を突き進み、障害を越えて高速を維持しエネミーを倒し、何度も失敗と再スタートを繰り返しながら徐々に新たな能力とゲームプレイルートを解放していきます。

プロジェクト全体のデザインは非常に明確なメカニクスの理念を中心に展開されています：**スピードは力**。本作においてスピードは単なる移動能力ではなく、プレイヤーの攻撃強度・生存状態・戦闘効率に直接結びついたコアリソースです。プレイヤーは走る・ジャンプする・ダッシュする・ウォールスライドする・グラップルスイングするなどの動作を通じて継続的に運動量を維持しなければならず、スピードが低下すると攻撃効果が著しく低下し危険な状態に陥ります。スピードがゼロに長時間達するとキャラクターは即死します。このデザインにより移動システムは地形を突破するための手段にとどまらず、戦闘・リソース管理・サバイバルの意思決定と深く融合して、ゲーム体験全体の基本的な張力を形成しています。

### コアゲームプレイデザイン：スピード駆動の戦闘ループ

従来のプラットフォームアクションゲームと異なり、*Speed Pixel* はプレイヤーが高速状態で戦闘と移動操作を完成させることを求めます。ゲームのスピードバーは単なる表示コンポーネントではなく、プレイヤーの行動を誘導する重要なフィードバックシステムです。スピードの上昇とともにプレイヤーは異なるスピード段階に入り、より強いダメージ出力・追加攻撃効果・より効率的なエネミー一掃能力を獲得します。スピードが重要な閾値を下回るとキャラクターの出力能力が著しく低下し、戦闘とサバイバルの圧力が急速に高まります。このデザインによりプレイヤーは常に「さらに加速する」と「失速を避ける」の二重の動機によって行動することになります。

このコアループをサポートするために、スピードと連動した複数の移動メカニクスを設計しました。基礎レベルとして走る・ジャンプするがあり、上級レベルとしてエナジースフィアダッシュ・ウォールスライド・グラップルスイングなどの高機動アクションを追加しました。このうちエナジースフィアダッシュは *Ori and the Blind Forest* の方向ダッシュのデザイン思想を参考にしており、特定のインタラクションポイントに触れた後に指定方向に素早く移動することで、高リスクエリアを越えたり連続したリズムを維持したりできます。グラップルメカニクスはマップトラバーサルの表現力をさらに高め、複雑な地形でプレイヤーが高速スイングと移動の連携を完成させられるようにしました。これらのメカニクスが共同で、リズムとルート判断に高度に依存する移動システムを形成しています。

### 戦闘システム：高速制圧と弾幕出力の融合

戦闘デザインでは、従来の近接コンボシステムを採用せず、「高速移動」と「自動または半自動の火力出力」を組み合わせて、プレイヤーが継続的に前進しながらエネミーを一掃し制圧できるようにしました。プレイヤーはスピードで直接衝突ダメージを与えることができ、特定のスピード段階に達した後にエナジーウェーブを放出でき、さらに異なる効果を持つ弾を発射するさまざまなタイプのタレットや武器モジュールを装備することもできます。

シングルショット高ダメージ・デュアルショットバランス型・トリプルショット低ダメージ高頻度・範囲爆発能力を持つロケット型攻撃など複数の武器を設計しました。これらの武器はステータスの差異だけでなく、プレイヤーの戦闘リズムとビルドの方向性にも影響を与えます。例えば高バースト武器はエリートエネミーと重要な脅威目標の処理に適しており、高頻度弾幕武器は高速前進中の密集したエネミー群の素早い一掃に適しています。このデザインにより戦闘システムとローグライトビルドシステムが強い連携を形成し、毎回のプレイでプレイヤーが強化の選択に基づいて異なる戦い方を展開できます。

弾システムの実装においては、直線・ホーミング・貫通・爆発など複数の動作モードをサポートする統一ロジック構造を構築し、オブジェクトプールで高頻度の生成・破棄によるパフォーマンスオーバーヘッドを削減しました。特にエネミー密度が高く画面上の弾の数が多い場合でも、この構造により戦闘画面の安定性と明瞭さを維持できます。

### ローグライト成長構造：インランビルドとメタ成長の並存

再プレイ価値を高めるために、比較的完全なローグライト成長フレームワークを追加しました。プレイヤーは毎回の失敗後にスタート地点に戻りますが、ゲーム中に獲得したリソースを保持して永続的なアップグレード・能力ブランチ・新装備のアンロックに使用できます。一方で単一のプレイ中にランダムな強化オプションを通じて一時的なバフを獲得することで、変化のあるインランビルド体験を形成します。

この「二層成長」メカニクスは短期的なフィードバックと長期的な目標を同時に満たします。一方でプレイヤーは毎回新しい強化の組み合わせを試して異なる戦闘スタイルを体験でき、他方で失敗しても蓄積されたリソースで継続的な成長感を感じられ、繰り返しチャレンジする挫折感を軽減します。実装においてはスキルツリーシステムにユニークID・アンロック依存関係・コスト条件に基づく管理ロジックを設計し、データ駆動方式でスキルと能力項目を管理することで、後続の新アップグレードコンテンツの追加を容易にしました。

### プロシージャルマップ生成：ランダム性と遊び応えのバランス

マップ生成システムは本プロジェクトで最も力を入れたモジュールの一つです。ゲームが継続的な前進・再プレイ・ルートの変化を強調することを考慮して、モジュラーなチャンクアセンブリに基づくプロシージャル生成方式を採用しました。全体のシーンは異なる機能と地形特徴を持つ小型のプレハブチャンクシリーズで構成され、メインパスアルゴリズムと分岐生成ロジックによって完全なレベルフローに組み立てられます。

メインパスは主にノイズ関数を使用して自然な高低起伏を生成し、全体的な地形変化に一定のリズム感を確保します。分岐パスはパラメータ制御の頻度・距離・難易度に基づいて生成され、マップのランダム化後に通過不可能になったり面白みがなくなったりすることを防ぎます。システムにはまた衝突検出・パスの連続性チェック・局所密度制御も組み込まれており、チャンクの重複・ジャンプギャップ・無効な空間の問題を削減しています。この方法により、マップは強い再プレイの差異を維持しながらも、プラットフォームアクションゲームの「可読性」と「予測可能性」の基本的な要件を壊しません。

### ビジュアルスタイルとインターフェースデザイン

ビジュアル面では、*Speed Pixel* は極めてシンプルなピクセルアートスタイルを採用し、高コントラスト・強い識別性・高速移動時の可読性を強調しています。ゲームのペースが速いため、ビジュアルフィードバックのデザインでは複雑な装飾よりも情報伝達の効率を優先しました。キャラクター・エネミー・罠・インタラクト可能な要素はすべて明確なジオメトリアウトラインと明確な色の区別を可能な限り使用し、プレイヤーが高速移動中でも危険とルートの機会を素早く認識できるようにしました。

UI デザインは「最小限だが高い可読性」の原則に従っています。スピードバーはインターフェース全体で最も重要な情報コンポーネントであるため、位置・色の変化・段階的なフィードバックのデザインに重点を置き、プレイヤーが過度に注意を分散させることなく現在の状態を把握できるようにしました。また、アップグレード選択画面・メタショップ画面・リザルト画面も設計してローグライトのゲームプレイの成長とフィードバックループを担わせました。スピード感と打撃感を強化するために、パーティクルエフェクト・被弾変形・状態変化の色フィードバック・高速状態でのモーションビジュアル強化エフェクトも追加しています。

### 技術実装とエンジニアリング組織

プロジェクトは **Unity 6000+ LTS** と **C#** を使用して開発し、**URP** でピクセルスタイルのポストプロセッシングビジュアル表現を実現しました。アーキテクチャ面では、ゲームフロー管理・プレイヤーコントロール・武器と弾システム・マップ生成・スキルツリー・UI 管理・オーディオ制御・エフェクト制御など複数の独立したモジュールに分割し、イベントメカニズムでモジュール間の直接的な結合を削減しました。コアマネージャーは統一されたシングルトン基底クラスでライフサイクルを管理し、ランタイムデータは設定データと状態データを組み合わせて組織化して後続の反復と機能拡張を容易にしました。

開発効率と保守性を向上させるために、UI とキャラクターフィードバックアニメーションの処理に **DOTween** を、エディター設定効率の向上に **Odin Inspector** を使用し、統一された入力コントロールと時間コントロールロジックで一時停止・リザルト・非戦闘状態でのインタラクション動作を管理しました。パフォーマンス最適化では、マップチャンクのロード/アンロード・弾とエフェクトのオブジェクトプール管理・ポストプロセッシングとオーディオ再生のリソース消費の処理を重点的に行い、開発段階でプロジェクトの比較的安定した実行パフォーマンスを確保しました。

### テストと反復：クラス内プレイテストからの体験最適化

プロジェクトの完成段階では、授業が組織したクラス内プレイテスト展示に参加し、他の学生にゲームを体験してもらいました。自分の作品をより多くのプレイヤーに直接手にとってテストしてもらった初めての機会であり、非常にリアルで価値あるフィードバックを得ることができました。テストで集中的に指摘された問題には、チュートリアルのテキスト情報が多すぎて初期体験のペースに影響したこと、スピードバーの可読性がさらに向上できること、後半のエネミーの圧力が不足していてゲームの緊張感が低下すること、一部の操作は設計上深みがあるが初回体験時の誘導が十分に直感的でないことなどがありました。

これらの問題を受けて、プロジェクトに複数の調整を加えました。例えば、新規プレイヤー向けのチュートリアルでは大量のテキスト説明を削減してより直感的なビジュアルヒントと段階的な誘導に変更し、難易度デザインでは後半のエネミーの出現頻度を上げてスピード制圧能力がより高いエネミーと障害を追加し、インターフェースの情報階層とコントロールフィードバックを最適化してプレイヤーが「スピードを維持する」というコア目標をより理解しやすくしました。このテスト経験はデザインの盲点を見つけるだけでなく、ゲーム開発における遊び応えの検証とユーザーフィードバックの重要性をより深く理解させてくれました。
