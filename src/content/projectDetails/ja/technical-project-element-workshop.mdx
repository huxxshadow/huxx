## 担当

個人プロジェクトです。シミュレーションとレンダリングをすべて GPU で行うフォーリングサンド系サンドボックスで、世界は 512 × 288 のセルオートマトンです。各セルが砂の一粒、水の一滴、煙のひとすじ、あるいは固体の一部になります。

- **シミュレーション**：セルの移動、44 種類の反応、熱伝導、潜熱を伴う相変化、流体と煙の場、剛体を GPU のコンピュートパスで実装しました。Godot の物理エンジンは使っていません。
- **レンダリング**：Radiance Cascades による 2D グローバルイルミネーション、通過した物質の色に染まる光、サブサーフェススキャタリング、そしてライティングで平面の世界に奥行きを与える 2.5D ビュー。
- **最適化**：1 フレームあたりの GPU 時間を 7.9 ms から 3.5 ms に短縮し、全フレームの出力をバイト単位で同一に保ちました。
- **Web 版**：TypeScript と WebGPU に移植し、同じシェーダーソースを自動で変換しています。デスクトップとモバイルのブラウザで動き、中国語と英語に対応します。

| 項目 | 数 |
| --- | --- |
| 物質 | 85 種類（粉体、液体、気体、固体、エネルギー） |
| 反応 | 44 のペア反応ルール、ほかに燃焼と相変化 |
| コンピュートシェーダー | 45 本（GLSL 約 5,100 行） |
| 反応図鑑 | 100 項目、観察すると解放 |
| スクリプトデモ | 16 本 |

## シミュレーション

各セルは材質、温度、寿命、フラグを 1 つの `rgba32ui` テクセルに格納します。移動には **Margolus 2 × 2 ブロック** を使います。グリッドを重ならないブロックに分け、各スレッドが自分のブロックの 4 セルだけを並べ替えるので、書き込みの競合が起きません。1 tick に 8 回のサブステップがあり、ブロックの位置を交互にずらします。空気も物質の一つなので、粉体、液体、気体の浮き沈みは同じ密度比較で決まります。

反応は反応物ペアの 256 × 256 ルックアップテーブル（確率と温度範囲つき）から引き、各ブロック内で隣り合うペアごとに評価します。熱はセル間で拡散し、相変化は潜熱を吸収または放出します。1/4 解像度の流体ソルバーが熱い空気の浮力と爆風を、1/2 解像度の媒質場が煙、蒸気、炎を扱います。

## ライティング

ライティングは **Radiance Cascades** による 2D グローバルイルミネーションです。どのセルも光を放つことができ（火、溶岩、ランプ、発光する物質）、どのセルも RGB の 3 チャンネルで光を減衰させます。そのため緑の塩酸、青い水、赤いガラスを通った光は色づき、壁に色のついた光を落とします。氷、結晶、ゼリーのような半透明の物質では光が内部で散乱し（サブサーフェススキャタリング）、表面には鋭いハイライト用のクリアコート層があります。

グローバルイルミネーションとは別に、窓から差し込む日光、吊りランプの光束、鏡で反射した光束をそれぞれのパスで追跡し、最後にブルーム、自動露出、AgX トーンマッピング、カラーグレーディング LUT で仕上げます。

## 2.5D ビュー

形は常に二次元のままで、奥行きはライティングだけで表現します。最終画像は 1 本のビューシェーダーが合成します。各ピクセルの視線は、数セルの厚みを持つ板として扱うプレイ層を通り、続いて窓、柱、岩壁からなる背景のレリーフを通ります。

- **レリーフ法線**：輪郭が光の方へ傾いたり離れたりして、縁が浮き彫りのように光を受けます。
- **界面**：水、ガラス、氷の表面で視線が屈折率に従って曲がり、フレネル反射はシーンへ追跡し直されます。
- **背景**：レリーフは奥行きに応じてぼかした光で照らされ、前景の影、水の後ろのコースティクス、接触による遮蔽が入ります。
- **空気感**：層の間の霞、空気遠近法、昼夜のサイクル、カメラ移動時のわずかな視差。

## パフォーマンス

固定フレームレートではシミュレーションが決定的なので、結果を変えない最適化は同じフレームを正確に再現しなければなりません。テストスクリプトが 9 つのシーンを描画し、パスごとの時間を計測して、各スクリーンショットを参照画像とバイト単位で比較します。すべて一致した最適化だけを残しました。

| 変更 | 考え方 |
| --- | --- |
| 日光プローブ | 各日光レイが最初に物質に当たる位置を並列に求め（区間ごとの `atomicMax`）、光束パスはそこまでだけを追跡する |
| 分光光束 | ランプと日光の光束の 8 波長パス（分散）を 1 回の dispatch で並べて実行し、それぞれワークグループの 1 層を使う |
| 液体の拡散 | セル単位の複数パスの代わりに、行の区間を共有メモリで走査する |
| 圧力ソルバー | 20 回の dispatch の代わりに、すべての Jacobi 反復を 1 回の dispatch 内の共有メモリで行う |
| 空きパス | プレイヤー入力のない tick ではコマンドパスを省く |

最も重いシーン、1536 × 864 で、1 フレームあたりの GPU 時間は **7.9 ms から 3.5 ms** になり、出力は完全に同じです。

## Web 版

Godot は C# プロジェクトを Web に書き出せず、Web 用レンダラーにはコンピュートシェーダーもありません。そこでゲームを **TypeScript + WebGPU** に移植しました。GLSL は唯一のソースのままです。ビルド時に glslang で SPIR-V にコンパイルし、naga で WGSL に変換して、WebGPU が許さない部分を書き換えます。

| デスクトップ（Vulkan） | Web（WebGPU） |
| --- | --- |
| プッシュ定数 | dispatch ごとに動的オフセットを持つ uniform buffer |
| 結合イメージサンプラー | テクスチャとサンプラーのバインディングに分割 |
| 読み書き可能な `rgba32ui` イメージ | 読み取り用のコピーと書き込み専用のターゲット |
| バリア前の非一様な制御フロー | バリアが一様になるようシェーダーを再構成（デスクトップの出力は不変） |

物質、反応、マップは Godot プロジェクトから書き出し、両方のバージョンで同じデータを使います。ブラウザ版には中国語・英語の切り替え、タッチ操作（1 本指で描画、2 本指で移動とズーム）、スマートフォン向けのコンパクトなレイアウト、自動画質調整があります。

初回の読み込みは遅いものでした。ブラウザは最初の読み込みですべてのパイプラインをコンパイルし、D3D のシェーダーコンパイラーはすべての関数呼び出しをインライン展開するため、メインのビューシェーダーが約 60,000 行に膨らんでいたのです。使われていない分岐を削除し、すべての反射レイを 1 回のトレース呼び出しにまとめることで 16,000 行になり、初回読み込みは **13.9 秒から 3.2 秒** に短縮しました。デスクトップの画面は 1 ピクセルも変わっていません。
