## Project Details

**AI PixelArt Repair Tool** is an image repair tool oriented toward game development and pixel art workflows, primarily used to optimize "pseudo-pixel-style" assets generated by AI drawing tools such as MidJourney. While such AI tools can rapidly produce high-quality visual sketches, the generated results typically suffer from unclear pixel boundaries, uncontrolled color counts, locally damaged edges, and inconsistent grid structures, making them difficult to use directly in 2D pixel game projects.

To improve asset usability and reduce the cost of manual post-editing, I developed this tool, integrating "pixelation processing," "color quantization," "edge detection and repair," and "pixel block analysis" into a unified workflow. Users can flexibly combine different algorithms based on asset characteristics, quickly obtaining results closer to true pixel art standards, significantly improving development efficiency and asset quality.

### Pixelation and Color Quantization Pipeline

The core goal of this tool is to convert AI-generated images from "high-resolution illustration logic" to "pixel art logic." To this end, I implemented multiple pixelation approaches, including classic nearest-neighbor pixelation, mosaic effects, oil-painting-style pixelation, and hierarchical pixelation. Different algorithms suit different types of input assets: some better preserve outlines, others better emphasize block-face character, and users can achieve different degrees of abstraction by adjusting pixel block size.

For color control, I added multiple color quantization algorithms: **K-Means clustering**, **Median Cut**, **Floyd-Steinberg Dithering**, and perceptual-weight-enhanced variants. The goal is to compress color counts and unify the color palette while preserving the main structure and readability of the image. This step is especially critical for pixel style unification, since AI-generated images often contain too many intermediate and noise colors, causing the image to look "impure" or "muddy."

### GPU-Accelerated Color Clustering Optimization

To make the tool more usable in real production environments, I specifically optimized for performance bottlenecks. K-Means clustering for color quantization has high computational cost when processing high-resolution images — relying entirely on CPU results in noticeably slower processing, especially when users need to try multiple parameter combinations and batch-export results, making wait times very costly.

I therefore integrated **cuML** and **cuPy** from the RAPIDS stack, migrating K-Means clustering and related array operations to the GPU. This gives the tool noticeably improved response speed when processing large images, running high-frequency parameter experiments, or generating multiple results in parallel. For game development workflows that need to quickly validate multiple pixel style approaches, this acceleration is not simply "runs faster" — it directly improves creative iteration efficiency.

In the design, I also preserved a CPU version as a compatibility fallback, making the tool runnable in ordinary local environments while also enabling GPU mode in CUDA-capable Linux / Windows WSL environments, balancing ease-of-use with extensibility.

### Edge Repair and Image Structure Cleanup

Beyond pixelation and color compression, I also designed a dedicated repair module for the "dirty edges" problem most common in AI-generated images. This module is based on **Canny edge detection** and a custom **neighborhood averaging repair algorithm**, primarily addressing issues such as abnormal outline aliasing, edge breaks, local noise, and structural damage.

Users can control edge detection sensitivity by adjusting Canny's high and low thresholds, and further refine edge region detection quality through morphological operations such as dilation and erosion. For identified abnormal regions, the system applies neighborhood averaging with adjustable parameters for smoothing and repair, making originally broken or unnatural edge transitions more unified.

This module is particularly suited for fixing details in AI-generated pixel images that "look like pixel art but don't hold up when zoomed in." Although edge repair may introduce some blurring, in the tool design I emphasize that it should be used together with the pixelation module: first clean up structure, then re-establish pixel block relationships, to obtain results that are more natural and better match game asset standards.

### Interactive Interface and Multi-Result Comparison Workflow

To lower the barrier to use, I built an interactive web interface for the project using **Gradio**. Users can directly upload images, select pixelation methods, configure color quantization algorithms, and adjust parameters to view output results in real time — no additional coding required. Compared to traditional command-line script tools, this approach is better suited to art iteration, design review, and rapid experimentation.

I also designed the tool with multi-threaded processing and simultaneous multi-variant output capability. Users can select multiple pixelation algorithms and multiple color quantization strategies at once, and the system generates different style results in parallel for side-by-side comparison, making it easy to choose the version that best matches the current project's visual standards. This "results side by side" design significantly reduces the cost of parameter experimentation, and genuinely transforms the tool from "algorithm demo" to "production-ready assistant tool."

### Pixel Block Detection and Standardization Analysis

Beyond direct image processing, I also added a **Pixel Block Detection Tool** for analyzing common pixel block sizes in pixel-art-style images. This module scans color changes in the image combined with contour detection to infer the most common color block size, helping users judge whether the current image's grid structure is consistent.

This feature is very practical for pixel art workflows. In real projects, assets often come from different sources — AI-generated, hand-drawn, outsourced, historical asset libraries — and they may not conform to a consistent pixel grid standard. Through pixel block detection, users can more quickly determine whether an asset is suitable for the current project, or use the result to guide pixelation parameter settings in reverse, improving consistency across the entire asset production pipeline.

### Project Value and Practical Significance

Although this project had only a one-week development cycle, it solves a very practical problem: **how to convert AI-rapidly-generated visual assets into assets that are truly usable in pixel game production.** In indie or small-team projects, AI tools can greatly speed up early concept output, but without a subsequent style correction workflow, these assets often cannot enter the formal development stage directly.

The significance of **AI PixelArt Repair Tool** is that it toolizes, parameterizes, and visualizes what were originally scattered, repetitive, and manual-experience-dependent processing steps. It not only improves asset editing efficiency, but also established a more complete "AI generation → automatic optimization → asset delivery" production pipeline for my own subsequent game projects. For me, this is not just an image processing tool — it is a practice in genuinely combining machine learning, computer vision, and game development workflows.
