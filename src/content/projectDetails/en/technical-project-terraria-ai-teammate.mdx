## My Role

A solo project at the intersection of **games and AI**: an AI teammate for *Terraria* that follows the player and helps in combat. It uses a traditional behaviour tree as its framework and hands most decision nodes to the Jev model, while the tree handles flow orchestration, real-time reactions and fallbacks.

- **Decision architecture**: Designed the layered "LLM brain + Jev cerebellum + behaviour tree" structure, decided which gates go to Jev and which stay as code reflexes, and distilled the rule that keeps this split sound in a real-time game.
- **Jev nodes**: Designing the questions, the state snapshots they see, the symmetric option wording, the confidence thresholds, and the asynchronous plumbing that lets a 300 ms answer live inside a 16 ms tick.
- **Classical layer**: Pathfinding whose jump and flight arcs are traced from the game's physics, lead aiming, dodging, and a boss ring that never closes.
- **Brain layer (LLM)**: ChatGPT writes a survival playbook per boss and a mining plan; as upper-level strategy these set the conditions and state snapshots of the Jev nodes, rather than issuing key presses directly.

## Design Approach

The system uses a layered "brain + cerebellum" structure: the LLM handles strategy, Jev handles judgment, and the behaviour tree and code handle execution.

**The problem: hand-authored condition nodes.** A traditional behaviour tree leans heavily on hand-authored conditions to choose between states: every "should I retreat" or "which weapon now" has to be written in advance as a fixed rule, which gets tedious and rigid once combat states become complex.

**Layer one · Jev as the cerebellum: replacing judgment nodes.** The small nodes that need to weigh complex state are replaced with Jev. Its inference speed lets each node judge the current situation directly at runtime, while the tree keeps its clear flow structure.

**Layer two · the LLM as the brain: setting conditions dynamically.** The Jev nodes are not fixed either. An upper-level LLM reads the overall situation and long-term goals and adjusts the preset conditions inside each Jev node, so the same tree makes different trade-offs across bosses and phases.

| Layer | Role | Responsible for | Update rate |
| --- | --- | --- | --- |
| LLM (ChatGPT) | Brain | Reads the situation and goals, sets the Jev nodes' conditions | Once per boss; mining plan every 12 s |
| Jev nodes | Cerebellum | Fast judgment over complex state | About 300 ms per answer |
| Behaviour tree and code | Execution | Flow orchestration, real-time reactions, fallbacks | 30 ticks per second |

## Anatomy of a Jev Node

A Jev node is a gate whose condition is a judgment rather than a comparison. Each one has the same five parts.

**A snapshot.** Code builds a small structured state with only what the question needs: health, whether he was hit in the last two seconds, the boss's distance and closing speed, how much ground lies each way. Numbers a person would notice, not a dump of the world.

**A question with symmetric options.** Every option names both what it buys and what it costs. The first weapon question described melee only by its limit and ranged only by its advantage, and the model picked the bow six times out of six, including against a zombie two tiles away. Giving every option a reach and a cost took it to four out of five. A question that leans in its wording leans hard enough to be unusable while reading perfectly reasonably.

**A typed answer and a threshold.** A choice comes back with a probability per option and a confidence; a noul comes back as a probability of yes. The threshold is set per question from measurement, not by default: three weapons spread the probability, so the weapon node acts on confidence 0.35, while the "drink now" node acts on 0.5.

**Asynchrony.** The tree ticks thirty times a second; an answer takes about 300 ms. The node never waits. It reads the latest answer for its channel, asks again in the background when the snapshot's key has changed, and one request per channel is in flight at most.

**A fallback.** Without an answer, or below the threshold, the gate runs a plain rule: the hardest hitter, a health floor, a scored exit. The teammate is never smarter than the model, but never dumber than a scripted one.
