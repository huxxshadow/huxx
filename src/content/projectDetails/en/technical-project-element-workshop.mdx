## My Role

A solo project: a falling-sand sandbox in which the simulation and the rendering both run entirely on the GPU. The world is a 512 × 288 cellular automaton; every cell is a grain of sand, a drop of water, a wisp of smoke or a piece of a solid body.

- **Simulation**: Cell movement, 44 reactions, heat transfer, phase changes with latent heat, fluid and smoke fields, and rigid bodies, as GPU compute passes. The game does not use Godot's physics.
- **Rendering**: 2D global illumination with Radiance Cascades, light coloured by the matter it passes through, subsurface scattering, and a 2.5D view that gives the flat world depth through lighting.
- **Optimisation**: Through extensive optimisation, cut GPU time per frame to 3.5 ms while keeping every frame byte-identical.

---

## Light Transport

Lighting is 2D global illumination with **Radiance Cascades**. Every cell can emit light (fire, lava, lamps, glowing matter) and every cell attenuates it with an RGB extinction, so light passing through green acid, blue water or red glass is tinted and casts coloured light onto the walls. Translucent materials such as ice, crystal and jelly scatter light inside their bodies (subsurface scattering), with a separate clear-coat layer for sharp highlights.

On top of the global illumination, separate passes trace sun beams through windows, beams from hanging lamps and beams reflected by mirrors; bloom, automatic exposure, AgX tone mapping and a colour-grading LUT finish the image.

## Simulation

Each cell stores its material, temperature, lifetime and flags in one `rgba32ui` texel. Movement uses **Margolus 2 × 2 blocks**: the grid is split into blocks that never overlap, so every thread rearranges its own four cells without write conflicts. Eight sub-steps per tick alternate the block offset. Air is a material too, so sinking and floating follow the same density comparison for powders, liquids and gases.

Reactions come from a 256 × 256 lookup table of reactant pairs with probabilities and temperature windows, evaluated for neighbouring pairs inside each block. Heat diffuses between cells; phase changes absorb or release latent heat. A quarter-resolution fluid solver adds hot-air buoyancy and blast waves, and a half-resolution medium field carries smoke, steam and flame.

## Fire and Explosions

Flammable materials ignite above their ignition temperature and spread fire to their neighbours. Flames feed the medium field, which glows, rises with the fluid solver and lights the scene. Explosions write pressure into the fluid field, so the blast pushes powders, liquids and loose bodies outward.

## 2.5D View

Shapes stay two-dimensional; depth comes from lighting. The final image is composed by one view shader that marches each pixel's ray through the playable layer, treated as a slab a few cells thick, and then through a background relief made of windows, pillars and rock walls:

- **Relief normals**: Outlines lean towards or away from the light, so edges catch light like carved relief.
- **Interfaces**: Rays bend at water, glass and ice according to their refractive index; Fresnel reflections are traced back through the scene.
- **Background**: The relief is lit by depth-blurred light, with shadows cast by the foreground, caustics behind water and contact occlusion.
- **Atmosphere**: Haze between the layers, aerial perspective, a day–night cycle and a slight parallax when the camera moves.

## Performance

The simulation is deterministic under a fixed frame rate, so an optimisation that keeps the result must reproduce the same frames exactly. A test script renders 9 scenes, times every pass and compares each screenshot byte for byte with the reference; an optimisation only stays if all of them are identical.

| Change | Idea |
| --- | --- |
| Sun-beam probe | A parallel probe finds where each sun ray first meets matter (`atomicMax` over ray segments), so the beam pass only traces that far |
| Spectral beams | The 8 wavelength passes of lamp and sun beams (dispersion) run side by side in one dispatch, one workgroup layer each |
| Liquid spreading | Row segments scanned in shared memory instead of cell-by-cell passes |
| Pressure solve | All Jacobi iterations in one dispatch in shared memory instead of 20 dispatches |
| Idle passes | The command pass is skipped on ticks without player input |

GPU time per frame went from **7.9 ms to 3.5 ms** on the heaviest scene at 1536 × 864, with identical output.

## Web Version

Godot cannot export C# projects to the web, and its web renderer has no compute shaders, so the game was ported to **TypeScript + WebGPU**. The GLSL stays the single source: a build step compiles it to SPIR-V with glslang, translates it to WGSL with naga, and rewrites what WebGPU does not allow:

| Desktop (Vulkan) | Web (WebGPU) |
| --- | --- |
| Push constants | A uniform buffer with a dynamic offset per dispatch |
| Combined image samplers | Separate texture and sampler bindings |
| Read-write `rgba32ui` images | A read copy plus a write-only target |
| Non-uniform control flow before barriers | Shaders restructured so barriers stay uniform (desktop output unchanged) |

Materials, reactions and maps are exported from the Godot project, so both versions share the same data. The browser build has a Chinese / English switch, touch controls (one finger paints, two fingers pan and zoom), a compact layout for phones and an automatic quality setting.

The first visit was slow: browsers compile every pipeline on first load, and the D3D shader compiler inlines every function call, which expanded the main view shader to about 60,000 lines. Removing a dead branch and routing all reflection rays through a single trace call reduced it to 16,000 lines, and the first load from **13.9 s to 3.2 s**, without changing a pixel on desktop.
