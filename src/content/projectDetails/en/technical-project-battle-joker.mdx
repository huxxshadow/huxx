## My Role

In this two-month, three-person multiplayer game development project, I served as team leader and lead developer, primarily responsible for overall technical solution design, core system development, and team collaboration. My specific responsibilities included:

* **Project Management and Technical Solution Design**: Responsible for breaking down project requirements, planning the development schedule, assigning member tasks, and coordinating development progress across client, server, and testing modules to ensure on-time delivery.
* **Multiplayer Network Architecture and Core Logic Development**: Led the design and implementation of a client-server multiplayer battle architecture supporting up to four players in real-time matches in the same room, and implemented core features including turn synchronization, state broadcasting, win/loss determination, and score tracking.
* **Server Performance Optimization and High-Concurrency Support**: Introduced layered architecture, thread pools, and object pools on the server side to improve resource utilization and system stability under high-concurrency scenarios, ensuring smooth multiplayer gameplay.
* **Leaderboard and Monitoring Module Development**: Implemented real-time leaderboard broadcasting functionality and participated in developing a server monitoring interface for viewing online players, room status, and server operational conditions.
* **Testing Organization and Deliverable Integration**: Responsible for organizing integration tests and stress tests to verify system stability under large-scale client connections, while integrating the project report, demo content, and final deliverable version.

## Project Details

This project extended an existing single-player card merging game with online multiplayer battle functionality, aiming to enhance interactivity and competitiveness while preserving the fun of the original gameplay. The game mechanics draw from 2048's merging logic, but replace numbers with playing card sequences — players merge adjacent identical cards to continuously upgrade card ranks and ultimately merge to create a Joker for victory; when the board can no longer merge, the game ends. Around this core gameplay, we implemented an online version supporting up to four simultaneous players, using a client-server architecture to centrally handle room management, player turns, state synchronization, and data storage. The server maintains game state, processes player actions, and synchronizes match results; the client handles interface display and interaction feedback, ensuring all players receive a consistent real-time experience. Beyond this, the project added features including historical top-ten score records, real-time leaderboards, save/load functionality, and server monitoring, making the system not only fully capable for online multiplayer but also highly maintainable and extensible. To address the performance pressures of multiple simultaneous online players, we adopted a layered development approach in the architecture, combining thread pools and object pools to optimize high-frequency message processing and memory allocation, reducing performance overhead and resource waste. The later project stages also included fairly comprehensive stress testing, verifying system stability under high-concurrency scenarios by simulating large numbers of client connections. Overall, this project completed the upgrade from single-player to online multiplayer gameplay, and gave me systematic practice in network game architecture design, server performance optimization, and team collaborative development.
